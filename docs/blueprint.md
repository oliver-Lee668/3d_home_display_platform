## 1. As-Is：当前已落地的一期闭环

一期解决的问题是「**客户定制 → 生产执行读数回流**」这条主链路线上化，覆盖订单流与执行流两条线。

### 1.1 业务泳道（as-is）

```
客户                销售端                  生产端                  车间(工人)           管理层
 │                   │                       │                        │                  │
 │ 3D 展厅浏览/定制   │                       │                        │                  │
 │ (WebGL 配置器)     │                       │                        │                  │
 ├─ 提交订单 ────────►│                       │                        │                  │
 │  (验证码+限流)     ├─ 审单/确认 ──────────►│                        │                  │
 │                   │  (可退回，留痕)        ├─ 确认排产               │                  │
 │                   │                       │  状态→生产中            │                  │
 │                   │                       ├─ 打印工单(含二维码) ───►│                  │
 │                   │                       │                        ├─ 扫码领活(开工)   │
 │                   │                       │                        ├─ 完工报数         │
 │                   │                       │                        │  (合格/废品)      │
 │                   │                       │◄── 报工流水实时落库 ────┤                  │
 │                   │                       ├─ 工单行进度可见         ├──────────────────►│ 车间看板
 │                   │                       │  (合格 x/y)            │                  │ (大屏轮询)
 │                   │                       ├─ 全部完工→标记完成      │                  │
 │◄─ 双因子自助查单 ──┤                       │                        │                  │
 │  (订单号+手机号)   │                       │                        │                  │
```

### 1.2 系统组成（as-is）

| 层 | 组件 | 技术 | 职责 |
|---|---|---|---|
| C2M 入口 | 客户 3D 展厅 | React 18 + three.js/R3F + Vite | 浏览、摆放、材质/尺寸定制、下单、查单 |
| 业务前台 | 销售确认台 | React（同一代码库，构建期角色分流） | 目录维护（商品/地板/规格基线）、审单、退回 |
| 业务前台 | 生产确认台 | React | 接单排产、工单拆单（按车间）、打印/导出 CSV |
| 执行层 | H5 扫码报工 | React + BarcodeDetector | 工人扫工单二维码领活、完工报数（合格/废品） |
| 管理层 | 车间看板 | React + 8s 轮询 | 在制/今日合格/废品/折算工时、车间分组进度、流水 |
| 服务层 | Go API | Go 1.24 stdlib net/http | 订单/目录/账号/报工/看板聚合，RBAC + 动作级校验 |
| 数据层 | MySQL 8 | 4 张表 | orders / catalog_entries / users / work_reports |

### 1.3 一期已固化的管理规则

- **状态机**：`submitted → sales_confirmed → in_production → completed`，任意环节可 `rejected` 退回销售；每次流转留痕（操作人取自登录 token，不可伪造）。
- **两层权限**：路由级角色门禁（sales / production / admin）+ 动作级校验（如报工仅生产角色、目录维护仅销售/管理员）。
- **规格快照**：下单瞬间冻结工艺/工时/图纸等生产依据，销售事后改目录不影响已下工单；毫米尺寸由服务端按基线重算，客户端不可伪造。
- **超报防护**：工单行合格数累计不得超过计划件数，废品不占合格额度；仅「生产中」订单可报工。
- **报工人可信**：worker 字段由后端从 token 写入（`角色:显示名`），前端无操作人输入框。

### 1.4 一期的边界（明确没做的）

- 无 BOM / 物料库存：主材 SKU 只是快照字段，不做扣减。
- 无排程（APS）：工时只做「折算读数」，不生成排产计划。
- 无设备联网：报工靠人扫码，不采集设备信号。
- 单租户：无企业隔离，看板与账号都是一厂一套。

## 2. To-Be：二期蓝图

二期方向 = 把「执行读数」升级为「**计划-执行-结算**」三段闭环，向 ERP/MES 标准形态靠拢。

### 2.1 目标泳道（to-be）

```
销售          计划(新增)         车间               仓储(新增)          管理层
 │               │                │                   │                 │
 ├─ 订单确认 ───►│                │                   │                 │
 │               ├─ BOM 展开      │                   │                 │
 │               ├─ 物料齐套检查 ─┼──────────────────►│                 │
 │               │  (缺料预警)    │                   ├─ 领料/退料       │
 │               ├─ 有限产能排程  │                   │                 │
 │               │  (APS 简版)    │                   │                 │
 │               ├─ 派工单 ──────►│                   │                 │
 │               │                ├─ 扫码报工(沿用)    │                 │
 │               │                ├─ 工序级报工        │                 │
 │               │                │  (开料/封边/打孔…) │                 │
 │               │                ├─ 完工入库 ───────►│                 │
 │               │◄── 计划达成率 ─┤                   │                 │
 │               │                │                   ├────────────────►│ BI 看板
 │               │                │                   │                 │ (交期达成/人效/
 │               │                │                   │                 │  废品率趋势)
```

### 2.2 二期模块与一期资产的复用关系

| 二期模块 | 内容 | 复用一期什么 | 新增什么 |
|---|---|---|---|
| BOM 与物料 | 商品→物料清单，齐套检查，领料扣库存 | catalog_entries 的规格基线（materialSku 已在快照里） | materials / boms / stock_ledger 表；仓储角色 |
| 工序级报工 | 一张工单行拆多道工序，逐工序报工 | work_reports 表结构与 H5 交互骨架 | routes（工艺路线）表；item_index 细化到 operation |
| 简易 APS | 按车间产能与工时排优先级，生成派工顺序 | 看板已聚合车间标准工时（laborMinutes） | 排程算法与派工单视图 |
| ERP/BI 集成 | 订单、出入库单据同步；经营层报表 | REST API + token 鉴权体系，直接对外开放只读接口 | 导出/订阅层；与用友/金蝶的单据映射 |

### 2.3 演进原则

1. **表结构只做加法**：work_reports 的冗余字段（order_no/item_name/workshop）就是为二期免联表聚合预留的，继续沿用「写入时冗余、读取时零 JOIN」的看板策略。
2. **角色只扩不改**：新增仓储/计划角色走现有 users.role + staffRoles 门禁，不动已固化的动作级校验。
3. **执行端不换枪**：工人侧继续使用 H5 + 扫码，不引入需要装 App 的方案；工序级报工只是在同一页面加深一层。
4. **先读数后结算**：BI 报表先基于报工流水做只读聚合（当前看板模式），跑顺后再引入计件工资结算。
